## Files
- `src/<char>.glb` are the final, Interchange-ready GLBs: `hayk`, `ara` (crown merged), `bel`, `babsold`, `armsold` (helmet merged),
  `armsoldc`, `babsoldc` (crowd variants), `shamiram` (skinned). `src/props/spear.glb` and `bow.glb` are flattened props.
- `dl/glb/<uid>.glb` and `dl/props/<uid>.glb` are the untouched downloads.
- `scripts/` holds the whole pipeline:
  - `chars.json`: per character, the source uid, parts to drop and props to attach (with fit arguments).
  - `prep_all.sh`: runs prep_char.py → bake_gltf_root.py → glb_attach_prop.py for each entry.
  - `glb_attach_prop.py` (new): fits a rigid prop to a bone's geometry (helmet/crown on `head`), skins it to that bone and merges it as one section.
  - `prep_rename_hik.py` + `bake_bind.py` (new): HumanIK/Mixamo bone names → UE names; skeleton rebuilt from the inverse bind matrices.
    Use these for any rigged Sketchfab model whose scene pose ≠ bind pose.
  - `skin_transfer.py` (new): skins any **static** humanoid onto the UE5 mannequin. Weights come from Quinn (exported from UE with
    GLTFExporter), with arm-pose matching, kNN weights and a pelvis blend for dresses. Needs numpy, scipy and `fast_simplification`
    (in `pylib/`). Shamiram was made with it.
  - `glb_crowd.py` (new): crowd LOD. It bakes each slot's M_Human grading into a colour/normal/MR atlas, merges everything into one
    section and decimates while keeping the weights.
  - `glb_flatten.py`: many-part static prop → one mesh.
  - `ue_chars_build.py`: Interchange import (no Nanite) + IK_Manny / IK_<Char> / RTG_Manny_to_<Char> + batch retarget of `CHARS_CLIPS`.
  - `ue_materials.py` + `mat_spec.py`: M_Human master + per-slot MIs + assignment.
  - `ue_lods.py`: SkeletalReduction LODs.
  - `ue_props.py`: solves the bow/spear socket offset from the clip pose.
  - Scenes: `ue_scene_*.py`. Runner: `run_ue.sh`. Screenshots: `shoot.sh`.

## Material: M_Human (one master, all characters)
The per-slot values are in `scripts/mat_spec.py`. Parameters:
- **Recolor1/2** (`Src`, `Dst`, `Amount`, `Width`, `Sens`, `KeepLum`): luminance-preserving hue replacement, with all values in linear
  space. It turns Andy's bright game dyes into period dyes: madder red `(0.55,0.09,0.06)` for Armenians, lapis `(0.09,0.17,0.48)` for
  Babylon, ochre and royal purple. It also removes the Celt's blue woad: `Dst (0.32,0.18,0.12)`, `KeepLum 0.1`, `Sens 3000`.
- **Saturation, Tint, Brightness, Roughness, Specular.**
- **MetalMask / ForceMetal / MetalTint / MetalTintAmount / MetalRoughness**: chrome becomes bronze `(0.78,0.48,0.22)` or gold `(1,0.75,0.38)`.
- **DirtAmount / DirtTiling**: noise grime. **DustAmount / DustHeight**: dust rising from the feet, using `PreSkinnedPosition.z`.
- **DetailNormalTex / DetailStrength / DetailTiling, Mottle**: skin pores and blotches.
- **CPD0/1/2** (CustomPrimitiveData): per soldier, `CPD0` = dye variation (towards `TintAlt`, × `TintVar`), `CPD1` = tone/fade (× `ToneVar`),
  `CPD2` = extra dirt. In C++: `Mesh->SetCustomPrimitiveDataFloat(0, FMath::FRand())` for 0, 1 and 2.
- **RimIntensity / RimColor, HitFlash / FlashColor**: same names as M_Hero, so the existing hit-flash code works on a MID.

Skin presets:
- Skin: Saturation .72, Roughness .62, Specular .38, Detail .5 @24, Mottle .1, Tint (.86,.76,.68).
- Cloth: Roughness .9, Specular .3, Dirt .25, Dust .55 @50 cm.
- Gold: ForceMetal 1, MetalRoughness .28, MetalTint (1,.75,.38).

Scales:
- Spartan/Celt bases are ~2.09 m and the Roman/Saxon ~1.75 m. Use Hayk ×0.84–0.95 (he is the giant), Ara ×0.82, Bel and soldiers ×1.0
  (or 0.95 to match Manny's 1.8 m).
- Shamiram is already 1.73 m.
- Mesh forward is +Y like Manny, so keep the existing yaw −90 mesh offsets.

## Performance (Iris Xe, 1600x900, 100% screen percentage, sunset scene with 3 CSM cascades, `stat unit`)
**Caveat:** during every measurement the iGPU was shared with 2–5 other agents' Unreal editors/games (serpent, aralez, highlands).
The *same* env-only map measured 17, 20, 27, 28, 32, 60 and 97 ms GPU. The table therefore shows the **minimum of 2–4 runs**, the
closest to a quiet laptop. Re-measure on a quiet machine with the maps `/Game/Proto/L_P0`, `L_Army`, `L_ArmyC`, `L_ArmyC60`
(`shots/pf*_s.png`, `perf_matrix*.jpg`).

| scene (game camera behind Hayk) | GPU min (ms) | Game thread (ms) | notes |
|---|---|---|---|
| env only (sky, fog, ground) | 17.2 | 3.5–4.4 | baseline |
| 10+10 full soldiers + Hayk + Bel | 30.7 | 8.1 | |
| 30+30 **full** soldiers (85k/225k tris, 6/13 sections) + spears | 55.3 | 11.9–18.4 | ≈ +0.6 ms GPU per soldier |
| 30+30 full, soldiers cast no shadow | 51.8 | 18 | shadows ≈ 7% of the soldier cost |
| 30+30 full, `r.SkeletalMeshLODBias 2` | 42.6 | 13.6 | LODs work |
| 30+30 **crowd** soldiers (12k/14k tris, 1 section) | 44.8 | 12.4–13.3 | ≈ −10…−25 ms vs full (noisy) |
| 30+30 crowd, `r.Shadow.CSM.MaxCascades 2` | 31.7 | 11.7 | ≈ −13 ms vs 3 cascades |
| 60+60 crowd (120 soldiers) | 38–49 | 19.3–28.3 | GPU did not scale linearly (contention noise); CPU anim eval ≈ 0.15 ms/soldier |

Recommendations to keep ≥ 50 fps (20 ms) on the presentation laptop:
1. Use the **crowd** meshes for every soldier further than about 8 m. Keep the full meshes for heroes and the first rank only.
2. Use **2 CSM cascades**, a shadow distance of about 40–60 m, and `SetCastShadow(false)` on ranks 3+ (blob or no shadows).
3. LODs: generated screen sizes are 0.35/0.15/0.06 (crowd) and 0.5/0.25/0.1 (full). On Iris Xe add `r.SkeletalMeshLODBias 1`.
4. CPU: URO + `OnlyTickPoseWhenRendered` are already set by the scene scripts. For ranks marching in step, use
   `Follower->SetLeaderPoseComponent(Leader)` (one anim eval for N soldiers). The AnimationSharing plugin does this automatically.
5. Distant masses (100+): use static pose snapshots (`USkeletalMeshComponent` → make static mesh, idle/walk keyframes) as HISM instances
   (1 draw per pose). The engine's AnimToTexture plugin would be the textbook answer, but its binaries in this engine build carry a stale
   BuildId and do not load. It would need an engine plugin rebuild.
6. Budget for 30–60 visible soldiers: 60 crowd soldiers with 2 cascades ≈ +14 ms over the env-only baseline.

## Findings / gotchas worth knowing
- **The 5.8 template `MM_Death_*` clips never reach the ground**: pelvis stays at 82–93 cm, they are stagger-into-ragdoll clips.
  - For fallen heroes, lay the posed mesh down: roll ±90° about the lateral axis, lift 14 cm. `L_B_fallen` does this (`shots/beauty_fallen.png`).
  - Alternatively, ragdoll on the Interchange-generated PhysicsAsset. In my editor-placed test the bodies fell through the floor, so this
    is untested in the game.
- **Cinematic depth of field renders stripes and magenta garbage on this Iris Xe/Vulkan driver** (`shots/beauty_v1_grid.jpg`). Do not use DOF.
- The retargeted `MF_Rifle_Idle_ADS` is a convincing bow draw (left arm forward, right hand at the cheek), and HaykArcher already uses it.
  A static bow's string stays straight. The game's existing StringTop/StringBottom code (string to the hand) is the right way to finish it.
- The Twilight project's Mannequins folder lacks the Walk/Jog/Rifle-aim clips that the full Template set has. The retargeted copies
  delivered here include them, so the game does not need the originals.
- Linear-space colours: a "crimson" of (0.30, 0.03, 0.05) linear displays as pink. Use about (0.10, 0.006, 0.012).
